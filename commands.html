gv

GitVerse from the command line

Work with GitVerse repositories, pull requests and issues without leaving the terminal.

gv <command> <subcommand> [flags]

Флаги

ФлагОписание
--helpShow help for command
--hostname <string>GitVerse hostname to operate against
-v, --versionShow gv version

Примеры

$ gv repo view veryviolet/gv
  $ gv pr list
  $ gv issue create --title "Bug" --body "..."
  $ gv api /user

gv api

Make an authenticated GitVerse API request

Make an authenticated HTTP request to the GitVerse API.

The endpoint is a path such as "/user" or "repos/{owner}/{repo}/pulls"; a full URL is also accepted. The placeholders {owner}, {repo} and {hostname} are filled in from the repository in the current directory.

The default method is GET, or POST when parameters are supplied. Parameters are sent as a query string for GET and HEAD, and as a JSON body otherwise.

With --paginate, every page of a collection is fetched and the arrays are merged into a single JSON array.

gv api <endpoint> [flags]

Флаги

ФлагОписание
-F, --field <key=value>Add a typed parameter in key=value format
-H, --header <key:value>Add an HTTP request header in key:value format
-i, --includeInclude the HTTP status line and response headers
--input <file>Send the contents of file as the body (use "-" for stdin)
-q, --jq <expression>Filter the JSON response with a jq expression
--limit <n>Stop after fetching n items when paginating
-X, --method <string>HTTP method for the request
--paginateFetch every page of a paginated collection
-f, --raw-field <key=value>Add a string parameter in key=value format
--silentDo not print the response body
-t, --template <template>Format the JSON response with a Go template

Примеры

# the authenticated user
  $ gv api /user

  # pull requests of the current repository
  $ gv api repos/{owner}/{repo}/pulls

  # every repository you can see, as a flat list of names
  $ gv api /user/repos --paginate --jq '.[].full_name'

  # create an issue
  $ gv api repos/{owner}/{repo}/issues -f title='Bug' -f body='Steps...'

  # close a pull request
  $ gv api -X PATCH repos/{owner}/{repo}/pulls/12 -f state=closed

gv auth

Authenticate gv with GitVerse

Manage the credentials gv uses.

GitVerse issues personal access tokens from the web interface; gv stores the token you paste in `$GV_CONFIG_DIR/hosts.yml` with 0600 permissions. The environment variables GV_TOKEN and GITVERSE_TOKEN take precedence over the stored credential and are never written to disk.

gv auth <command>

gv auth login

Authenticate with a GitVerse host

Store a GitVerse personal access token.

GitVerse has no OAuth device flow, so the token is created in the web interface and pasted here. Create one at https://gitverse.ru/settings/tokens and grant it the scopes the commands you intend to use require.

gv auth login [flags]

Флаги

ФлагОписание
-p, --git-protocol <string>The protocol to use for git operations: {https|ssh}
-h, --hostname <string>The GitVerse host to authenticate with
--skip-verifyStore the token without checking it against the API
--with-tokenRead the token from standard input

Примеры

# paste the token interactively
  $ gv auth login

  # read the token from a file, for scripts and CI
  $ gv auth login --with-token < token.txt

gv auth logout

Remove stored credentials for a host

Forget the token stored for a GitVerse host.

Tokens supplied through GV_TOKEN or GITVERSE_TOKEN are not stored by gv and cannot be removed this way; unset the variable instead.

gv auth logout [flags]

Флаги

ФлагОписание
-h, --hostname <string>The host to log out of

gv auth setup-git

Configure git to authenticate with the stored token

Register gv as a git credential helper for a GitVerse host.

Afterwards `git clone`, `git fetch` and `git push` over HTTPS use the token gv holds, so no separate git credential setup is needed.

gv auth setup-git [flags]

Флаги

ФлагОписание
-h, --hostname <string>The host to configure

gv auth status

Show the authentication state

Report which hosts gv has credentials for, where each credential came from, and whether it is still accepted by the API.

gv auth status [flags]

Флаги

ФлагОписание
-h, --hostname <string>Check a single host
-t, --show-tokenDisplay the token in the output
--skip-verifyDo not contact the API

gv auth token

Print the token gv would use

Print the authentication token gv resolves for a host.

Useful for feeding other tools, e.g. `curl -H "Authorization: Bearer $(gv auth token)"`.

gv auth token [flags]

Флаги

ФлагОписание
-h, --hostname <string>The host to look up

Примеры

gv pr

Work with pull requests

List, inspect and open pull requests.

Commands that take a pull request accept its number; inside a git checkout the pull request for the current branch is found automatically.

Note: the GitVerse API exposes no endpoint for merging a pull request, so gv has no "pr merge" command. Merge from the web interface.

gv pr <command>

Флаги

ФлагОписание
-R, --repo <OWNER/REPO>Select a repository using the OWNER/REPO format

gv pr checkout

Check out a pull request locally

Fetch the head of a pull request and switch to it.

gv first tries the server-side ref "pull/<number>/head". Not every GitVerse deployment publishes those refs, so it falls back to fetching the head branch directly from the fork it lives in.

gv pr checkout <number> [flags]

Флаги

ФлагОписание
-b, --branch <name>Local branch name to create

Примеры

$ gv pr checkout 42
  $ gv pr checkout 42 --branch review-42

gv release

Work with releases

Publish releases and attach build artefacts to them.

A release is identified by its tag; the tag must already exist in the repository, or be created from --target when the release is published.

gv release <command>

Флаги

ФлагОписание
-R, --repo <OWNER/REPO>Select a repository using the OWNER/REPO format

gv release create

Publish a release

Create a release for a tag and, optionally, attach files to it.

Files given as positional arguments or with --asset are uploaded once the release exists.

gv release create <tag> [<file>...] [flags]

Флаги

ФлагОписание
-a, --asset <files>Additional files to attach
-d, --draftSave the release as a draft
-n, --notes <string>Release notes
-F, --notes-file <file>Read the release notes from file (use "-" for stdin)
-p, --prereleaseMark the release as a prerelease
--target <string>Branch or commit the tag should point at
-t, --title <string>Title of the release

Примеры

$ gv release create v0.1.0 --title "gv 0.1.0" --notes-file CHANGELOG.md
  $ gv release create v0.1.0 dist/*.deb dist/*.rpm
  $ gv release create v0.2.0-rc1 --prerelease --target main

gv repo

Work with GitVerse repositories

Create, inspect, clone and fork repositories.

Commands that take a repository accept it as "OWNER/REPO"; run inside a git repository with a GitVerse remote and the argument can be omitted.

gv repo <command>

gv repo clone

Clone a repository locally

Clone a GitVerse repository.

Arguments after "--" are passed straight to git clone. When the repository is a fork, a remote named "upstream" is added for its parent.

gv repo clone <repository> [<directory>] [-- <git-flags>...]

Флаги

ФлагОписание
-p, --protocol <string>Clone protocol to use: {https|ssh}
--upstream-remote-name <name>Remote name to create for the parent of a fork

Примеры

$ gv repo clone gitverse/rest-api-description
  $ gv repo clone veryviolet/gv gv-cli
  $ gv repo clone veryviolet/gv -- --depth 1

gv repo create

Create a new repository

Create a repository on GitVerse.

Pass "OWNER/NAME" to create it inside an organization you belong to; a bare name creates it under your own account. New repositories are private unless --public is given.

gv repo create <name> [flags]

Флаги

ФлагОписание
--add-readmeInitialise the repository with a README
-c, --cloneClone the new repository afterwards
-d, --description <string>Description of the repository
--gitignore <templates>Gitignore templates to apply
--privateMake the repository private (default)
--publicMake the repository public
--templateMark the repository as a template

Примеры

$ gv repo create my-project --private --add-readme
  $ gv repo create myorg/service --description "Billing service" --public
  $ gv repo create tools --clone
